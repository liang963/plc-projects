# Modbus-RTU 多从站轮询（AM600，CODESYS 3.5）

用任务表驱动 Modbus-RTU 主站，轮询多台从站：每笔读写用一条任务描述（站号、功能码、地址、数量、数据），轮询器按序执行，并给出超时判定、数据有效性和逐从站故障诊断。

## 工程信息

| 项 | 内容 |
| --- | --- |
| 平台 | CODESYS 3.5 |
| 设备 | AM600 系列（工程内设备描述：1 路 RS485 + 1 路 CAN + 1 路以太网 + EtherCAT，16 点普通输入 / 8 点普通输出） |
| 编程 | 结构化文本（ST） |
| 规模 | 704 KB |
| 最近修改 | 2026-10-15 |

## 程序结构

| 对象 | 类型 | 作用 |
| --- | --- | --- |
| `PLC_PRG` | PROGRAM | 主循环：填写任务表、调用轮询器、汇总反馈 |
| `FB_ModbusRTU_Poller` | PROGRAM / FB | 轮询器：按任务表逐条收发 |
| `Bus` | 功能块实例 | Modbus 主站调用，参数 `Enable`、`TaskCount`、`PollDelay`、`WatchDog`、`Tasks` |
| `Tasks[]` | 任务数组 | 每笔读写一条记录 |
| `ModbusFaultofSlaveFlagArray` / `ModbusFaultofChannelFlagArray` | 诊断位图 | 逐从站 / 逐通道故障标志 |

## 任务表字段

| 字段 | 说明 |
| --- | --- |
| `Enable` | 该任务是否参与本轮轮询 |
| `Slave` | 从站号 |
| `FunctionCode` | 功能码，支持 3、4、6、16 |
| `Address` | 原始零起始寄存器偏移（不加 40001） |
| `Quantity` | 寄存器数量 |
| `Data[0..19]` | 写入数据 / 读回数据缓冲区（`ARRAY[0..19] OF WORD`） |
| `LastOK`、`Status`、`LastValue0` | 上一轮结果、状态字、首个寄存器值，用于诊断 |

## 任务表示例

站号 2 用三条任务完成「写频率 → 写控制字 → 读状态」：

| 任务 | 站号 | 功能码 | 地址 | 数量 | 数据 |
| --- | --- | --- | --- | --- | --- |
| 任务 4 | 2 | 6（写单寄存器） | `16#2001` | 1 | `Freq2` |
| 任务 5 | 2 | 6 | `16#2000` | 1 | `Ctrl2` |
| 任务 6 | 2 | 3（读保持寄存器） | `16#2100` | 4 | 读回状态 |

站号 3 复用同一套三段式（`Freq3` / `Ctrl3`），任务表下标顺延 `Tasks[7]`–`Tasks[9]`。

## 轮询参数

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `TaskCount` | 9 | 本轮参与轮询的任务数 |
| `PollDelay` | `T#30MS` | 相邻两笔报文之间的间隔，给从站留处理时间 |
| `WatchDog` | `T#10S` | 整轮超时看门狗 |
| `CurrentTask` | 输出 | 当前正在执行的任务下标，调试时直接看走到第几条 |

## 超时与数据有效性

读回的数据不是「读到就算数」，还要过两道判据：

**1. 单笔是否新鲜**（`Stale` 定时器，5 s）

```iecst
Stale1(IN := NOT (Bus.Completed AND (Bus.CurrentTask = 3) AND ReadOK1), PT := T#5S);
```

任务没跑完、或者这一笔读失败，定时器就开始计时；超过 5 s 没刷新，`Stale1.Q` 置位。

**2. 整站反馈是否可信**

```iecst
FeedbackVail1 := RunPolling AND Enable1 AND ReadOK1 AND NOT Stale1.Q AND NOT Bus.Fault;
```

轮询在跑、通道使能、本笔读成功、数据没过期、总线没报故障，五条同时成立才认为反馈有效；任何一条不满足，上位看到的就是「无效」而不是旧值。

## 关键点

- **地址按零起始填**：注释里明确「原始零起始寄存器偏移，不加 40001」，避免和手册的 4xxxx 编号混淆。
- **写读分离**：写频率、写控制字用功能码 6，读状态用功能码 3，同一从站的任务紧挨着排，一轮内完成一次闭环。
- **诊断到从站级**：`Status`、`LastOK`、`LastValue0` 加上故障位图，能直接看出是哪个从站、哪一笔掉线。
- **带宽友好**：30 ms 间隔 + 10 s 看门狗，9 条任务一轮约 270 ms，10 台从站规模的轮询也不会把 485 打满。
